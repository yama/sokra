# Sokra とソクラテスの産婆術

## この文書の目的

Sokra という名前の由来になっている「ソクラテスの産婆術」と、Sokra がそこから何を借りていて、何を借りていないかを整理する。

この文書は、古典的な思想史の厳密な解説ではなく、プロダクト設計の前提を共有するための資料である。

## 産婆術とは何か

ここで言う産婆術は、相手に答えを教え込むのではなく、問いを通じて相手の内側にある考えが外へ出てくるのを助ける対話のしかたを指す。古典的な産婆術はこれに加え、出てきた答えを矛盾によって崩し、相手をアポリア（途方に暮れた状態）へ導く「論駁（エレンコス）」の側面を持つ。

一般に連想されやすい要素は次の通り。

- 答えを外から与えるより、相手の中にあるものが出てくるのを助ける
- 相手の答えを受け取り、矛盾や前提を問い返すことで、思考が深まる余地を作る
- すぐに結論を確定せず、相手の言葉を手がかりに問いを進める
- 対話によって、まだ言葉になっていないものを少しずつ見えるようにする

## Sokra が着想を得ている点

Sokra が借りているのは、問いを通じて相手の中にあるものを外へ出しやすくする、という産婆術的な姿勢である。

- 参加者に最初から整理された答えを要求しない
- 誘導的な設問で結論へ押し込まない
- 直前の発話を受けて自然に次の問いを選ぶ
- 雑談や脱線も含めて、その人の中にある記憶や感覚が出てくる余地を残す

## Sokra が古典的な産婆術と違う点

Sokra は、古典的な産婆術をそのまま再現するプロダクトではない。

特に重要なのは、深い洞察や本質的な理解に到達する主体を、回答者本人に置いていないことである。

- 参加者に自己認識の変化や哲学的理解を起こさせることを主目的にしない
- 参加者を詰問したり、矛盾を突いて追い込んだりしない
- 対話の場でそのまま分析や解釈を返して、理解を確定させようとしない

Sokra の会話は、参加者の内省支援で終わるものではなく、あとから会話記録を読む主催者側の理解を深めるための入口として設計する。

## Sokra における理解の主体

Sokra が重視するのは、会話のその場で回答者が深い理解に至ることではなく、取得できた会話記録をもとに主催者が洞察を得ることである。

流れとしては次のように考える。

1. 参加者が、構えずに話せる会話を通じて断片的な感想や記憶を出す
2. Sokra は、その断片を過度に整形せず会話記録として残す
3. 主催者が複数の会話記録を読み返し、共通点や意外なズレを発見する
4. その過程で、主催者がセミナー設計や参加者理解について深い洞察に至る

つまり、Sokra は回答者を「深く分からせる」ための装置ではなく、主催者が「後から深く分かる」ための会話収集装置である。

## その前提での設計含意

この解釈に立つと、会話設計と運用設計の両方に改善余地がある。

### 会話設計

- その場で要約や分析を返しすぎない
- 回答者の言葉を整えすぎず、後から読める生の文脈を残す
- 取りこぼしをゼロにするより、自然さを崩さずに記録価値を確保する
- 回答者の理解促進より、主催者が読み返したときの解釈可能性を優先する

### 主催者向けの処理

- 会話記録を一覧・検索・比較しやすくする
- セッションごとの文脈やチェックポイント回収状況を後から追えるようにする
- 複数記録をまたいだ気づきを拾いやすい整理や集約を用意する

### 主催者向け UI

- 事前設定 UI: セミナー文脈、観測したい論点、避けたい誘導方向を定義する
- 記録確認 UI: 会話記録を読み返し、必要に応じて並べ替えや絞り込みができる
- 洞察支援 UI: 複数の会話記録から共通パターンや例外ケースを見つけやすくする

## まとめ

Sokra は、ソクラテスの産婆術のうち「問いによって相手の内側にあるものを外へ出しやすくする」という部分に着想を得ている。

ただし、深い理解の到達点は回答者ではなく主催者側に置く。この違いが、会話の作り方だけでなく、記録の残し方や主催者向け機能の優先順位も決める。
