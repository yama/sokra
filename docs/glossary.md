# Sokra 用語集

開発中に繰り返し出てくる言葉を揃えるための用語集。
UIラベルそのものではなく、設計・実装・議論で使う基準語を定義する。

## 役割

### 聞き手

会話AIの役割名。ゲストと雑談しながら感想を聞く側。
感想を作らせず、分析せず、話しやすい空気を作ることを主目的とする。
`src/prompt.js` のシステムプロンプトで定義されている。

- 備考: 技法だけでなく、人柄のよさが先に伝わる存在として設計する
- 備考: 細かい返答テクニックは補助であり、人格と会話姿勢を正本に置く

- 備考: 「インタビュアー」は情報を引き出す役という印象が強く、設計意図と合わないため使わない

### ゲスト

聞き手と会話する人。インタビューの対象者。
積極的に語ることを前提にしない。聞き手が場を作ることで会話が生まれる関係。

- 備考: 「回答者」は受け身の印象、「参加者」は特定イベントへの参加を前提にするため使わない
- 備考: システムプロンプト内では用途に応じて「セミナー参加者」など具体的に呼んでよい

### ホスト

インタビューを設置・管理し、会話記録を読み返す人。ゲストを迎える立場。
用途を問わない（セミナー、ユーザーリサーチ、採用など）。
将来的には、設定入力UIと記録閲覧UIを通じてシステムを利用する想定。

- 備考: 現時点ではホスト向けの専用UIは未実装

### 管理者

アカウントやシステム全体を管理する人。ホストより広い権限を持つ。
ホストが「インタビューを設置・運用する人」であるのに対し、管理者は「システムそのものを管理する人」。

- 備考: 現時点では未実装。単一組織での運用ではホストと同一人物になることもある

## 会話UI

### 開始画面

セッション開始前に表示される画面（`#startScreen`）。
モデル選択と開始ボタンを含む。開始ボタンを押すとメイン画面へ遷移する。

### モデル選択

開始画面にある、使用する Gemini モデルを選ぶドロップダウン（`#modelSelect`）。

### 開始ボタン

開始画面にある、セッションを開始するボタン（`#startBtn`）。
押下すると `InterviewSession#start()` が呼ばれ、メイン画面へ遷移する。

### メイン画面

セッション開始後に表示される会話画面（`#mainScreen`）。
チャットヘッダー・メッセージエリア・コンポーザー・デバッグパネルで構成される。

### チャットヘッダー

メイン画面上部の青いバー（`.chat-header`）。
タイトル・サブタイトルと進捗ドットを含む。ゲストに常時見える領域。

### メッセージエリア

メイン画面中央にある、バブルが積み上がるスクロール領域（`#messages`）。
AIタイピング表示・選択肢ボタン・クロージングカードもここに挿入される。

### AIタイピング表示

AIが返答前に表示する `...` のアニメーション。
英語では `typing indicator` が近い。

- 推奨呼称: AIタイピング表示
- 英語メモ: typing indicator
- 備考: 「AIが入力している感じを出す表示」と説明してもよい

### タイプライター演出

AIの返答テキストを1文字ずつ順に表示していく演出。
読みやすさとライブ感を演出する目的で使う。

- 英語メモ: stream display / typewriter effect
- 備考: `prefers-reduced-motion: reduce` 時は全文即時表示にフォールバックする

### バブル

UI上の1個の吹き出し（`.bubble`）。
`.msg.user` または `.msg.ai` の子要素として生成され、1つの `reaction` バブル、`question` バブル、`followup_question` に対応するフォローアップ、またはユーザー発言の表示単位になる。
ストリーミング中は親の `.msg` に `aria-hidden="true"` が付き、完了後に外れる。これにより、ライブリージョンが途中文字列を逐次アナウンスせず、完成済みバブルの全文を一度だけ読み上げる。

### 応答ターン

1回のユーザー入力に対して、AI側が返す応答のまとまり。
複数のバブルを含んでよく、典型的には `reaction` バブル群、`question` バブル、必要に応じて後続のフォローアップバブルで構成される。

- 備考: UI上の表示単位はあくまでバブルであり、応答ターンはそのまとまりを指す
- 備考: 実装上のセッションイベント type 値（例: `reaction`、`generated_turn`、`followup_question`）とは別概念。設計・議論用の呼び名として使う

### 選択肢ボタン

ボタンフェーズで、AIメッセージ（`.msg.ai`）の直下（バブルと同階層）に追加される選択肢（`.choice-btn`）。
選択後はボタンが無効化され、選択内容がゲストのメッセージとしてメッセージエリアに追加される。

- コード: `waitForChoice()`

### コンポーザー

発言入力欄と送信ボタンをまとめた入力エリア（`#inputArea`）。
フェーズによって表示・非表示が切り替わる。ボタンフェーズ中・終了後は非表示。CLOSINGフェーズでは、案内文（`closing_guide`）送信と終了ボタン表示のあとに再表示される。

- コード: `showComposer()` / `hideComposer()`

### 早期終了ヒント

自由会話フェーズでゲストのターン数が一定値（`EARLY_CLOSE_TURNS`）以上になったとき、メッセージエリア末尾に表示される「話題を変えて」「このくらいで」の2ボタン。
ゲストが会話を自分のペースでコントロールできるようにするためのUI。

- コード: `showEarlyCloseHint()` / `removeEarlyCloseHint()`

### 遊び入力ヒント

`playful` / `shiritori` 系のターンで `question` を出さずに止まったとき、メッセージエリア末尾に表示される「質問して」「このままで」「このくらいで」の3ボタン。
AI が無理に通常会話へ戻さず、次の進行だけをゲストに委ねるためのUI。

- コード: `showPlayfulHint()` / `removePlayfulHint()`

### クロージングカード

クロージングフェーズで表示される、案内文と「会話を終了する」ボタンをまとめたカード（`.closing-card`）。
ゲストが準備できたタイミングで会話を終了できるよう促す。

- コード: `renderClosingAction()` / `removeClosingAction()`

### デバッグパネル

メイン画面下部の開発者向けパネル（`#debugPanel`）。
チェックリスト・使用量表示・終了メモ・会話記録ダウンロードボタンをまとめた領域。
`APP_ENV=development` のときのみ表示される。

### チェックリスト

デバッグパネル内に表示される通過地点の達成状況一覧（`#checkItems`）。
各通過地点のラベルをテキストで表示し、達成状況はスタイルの変化（`.done`）で示す。

### 進捗ドット

チャットヘッダー内に表示される通過地点の達成状況を示す丸印（`#progressDots`）。
各通過地点が達成されると塗りつぶされる。ゲストに常時見える。

- 備考: `aria-hidden="true"` でスクリーンリーダーには非公開

### 自動フォロー

自由会話フェーズでゲストの発言に対するAI応答（`generated_turn`）後、一定時間（`FOLLOWUP_DELAY_MS`）が経過したら自動で追加の問いかけを送る仕組み。
通常会話ターン、または単発の遊び入力で単一絵文字待機にならなかったターンだけが対象になる。
直近ターンに `question` がある場合はスキップし、それ以外は予約される。話題切り替えや自動フォロー自身への応答後には予約されない。

- コード: `_scheduleFollowup()` / `type: "followup_question"`
- 備考: ゲストが返信した場合・入力中・セッションがビジーの場合はキャンセルまたはスキップされる

### ボタンフェーズ

会話冒頭の選択式フェーズ。自由入力の前に基本コンテキストを集める。

- 例: 参加形式、参加タイミング、温度感

### 自由会話フェーズ

ボタンフェーズ後の通常会話パート。
隠れたチェックリストを内部で持ちながら、自然会話で回収する。

## 会話設計

### セッションフェーズ

`InterviewSession` が内部で管理する状態。基本的には以下の順で遷移する。

| フェーズ | 定数 | 状態 |
|---------|------|------|
| 開始前 | `START` | セッション初期化前 |
| ボタン | `BUTTONS` | コンテキスト収集中 |
| 会話 | `CHAT` | 自由会話中 |
| クロージング | `CLOSING` | 終了フェーズ中 |
| 終了 | `ENDED` | セッション終了 |

- 備考: 通常は `START` → `BUTTONS` → `CHAT` → `CLOSING` → `ENDED` の順だが、放置タイマーによる `session_timeout_chat` やエラーによる `chat_failure_abort` などでは `CLOSING` を経ずに `ENDED` へ直行する

### 通過地点

会話の中で自然に回収したい内部トピック。
通常のゲスト向けUIには名称・内容を出さず、達成数のみ進捗ドットでゲストに示す。
開発時はデバッグパネルのチェックリストに各通過地点のラベルを表示する。

- 例: 参加背景、温度感、印象点、違和感・難しさ、実務との接点

### 反応

AIのレスポンスJSONに含まれる `reactions` 配列の各要素。相づちが自然なときだけ入れる独立した一言で、`question` とは分離して表示する。
どの発言にも使えそうな汎用的な相づちに寄りすぎない。

- 備考: 不要なときは空配列（[]）または省略
- 備考: 文脈外の短い入力では `reactions` のみで返し、`question` バブルを出さない場合がある

### 本文

AIのレスポンスJSONに含まれる `question` フィールドの値。
次に相手へ投げる問いの本体で、`reactions` とは別バブルとして表示する。

- 備考: 問いが不要なターンではキーごと省略される
- 備考: 設計・議論では `question` と英語フィールド名で呼んでもよいが、概念名は「本文」を優先する

### フォローアップ

応答ターンの後続として自動で追加される、続きを促す問い。
自由会話フェーズでは、最初の応答のあと一定時間が経過したときに送られることがある。

- コード: `_scheduleFollowup()` / `type: "followup_question"`
- 備考: コードやテストでは `followup` と書いてよい
- 備考: `reaction` や `question` と同じくバブルとして表示されるが、最初の応答とは役割を分けて扱う

### 話題切り替え

「話題を変えて」ボタンで発火する処理。
AI に「未収集の論点があれば自然に移る」よう内部プロンプトを送る。

- コード: `_switchTopic()` / `type: "topic_switch"`

### 放置タイマー

CHAT・CLOSING フェーズ中に一定時間（`ABANDON_TIMER_MS`）無操作が続いたとき、`session_timeout_chat` または `session_timeout_closing` イベントを記録してセッションを自動終了させるタイマー。
ゲストのメッセージ送信ごと、および自由会話フェーズ開始時・クロージングフェーズで終了ボタン表示後にリセットされる。
クロージング移行の冒頭では一旦停止し、ガイドメッセージと終了ボタンを表示したあとに再開する。

- コード: `_resetAbandonTimer()` / `_onAbandon()`

### 雑談フック

会話を自然に始めたり、少し横に広げたりするための軽い話題の取っかかり。
分析目的ではなく、摩擦を下げるために使う。

### 知覚のふり

AIが知覚を持っているように見える言い回しを使うこと。
話題として扱うのはよいが、観測事実として語ってはいけない。

- 避ける例: 「もう外は暗いですね」
- 許容例: 「そう言うことはできるけど、実際に外を見ているわけではない」

## 記録・運用

### セッション

`InterviewSession` の1インスタンス。`start()` の呼び出しからフェーズが `ENDED` になるまでの一連の流れを指す。
セッションIDを軸に、会話記録がサーバー側に保存される。

### セッションイベント

`pushSessionEvent()` で記録される会話・システムの各動作単位。
`role`（`"user"` = ゲスト / `"ai"` = 聞き手 / `"system"` = システム）と `seq`（連番）を基本フィールドとして持つ。`type`（イベント種別）と `text`（発言内容）は任意で、イベントの種類によって付加される。

- 例: `{ role: "ai", text: "…", type: "generated_turn" }`
- 例: `{ role: "user", text: "仕事終わりです" }` — type なし
- 例: `{ role: "system", type: "session_started", model: "…" }` — text なし
- 備考: クライアントのメモリと `/api/session/:id/event` の両方に逐次保存される

### ゲストコンテキスト

ボタンフェーズで収集した `format`（参加形式）/ `timing`（参加タイミング）/ `mood`（温度感）のセット。
`sessionContext` としてセッション中保持され、システムプロンプトと会話記録（`seminar_context` フィールド）の両方に使われる。

- 備考: コードの変数名 `sessionContext`・会話記録フィールド名 `seminar_context` はセミナー用途の現実装を反映した命名

### 用語方針

`ログ` という単語は単独では使わず、なるべく用途を明示する。

- 会話を保存したもの: 会話記録
- 開発や障害調査のためのもの: 開発ログ / アプリケーションログ / デバッグログ

### 会話記録

1回のインタビュー単位で保存された会話。
ゲストと聞き手（AI）のやり取りを中心に、`session_started` などの system イベントも含めて記録したもの。
現在は `data/sessions/*.jsonl` に保存する。

### 部分記録

途中離脱を含む未完了セッションの会話記録。
失敗扱いせず、価値のある記録として扱う。

### 開発ログ

動作確認、障害解析、デバッグのために出力する内部向けログ。
混同しやすいため、実装する場合は会話記録とは明確に分けて扱う。

- 例: サーバー起動ログ、APIエラーログ、デバッグ出力

### ready_to_close

Gemini の返答JSONに含まれる、AIが「会話を終了してよい」と判断したことを示すフィールド。
`true` のとき `_beginClosingPhase()` が呼ばれ、クロージングフェーズに遷移する。セッションの完了ではなく「終了を提案する」シグナルである点に注意。

- 備考: 旧名称 `is_done` から改名済み。会話完了ではなく「終了提案」の意味を表す。

### 使用量表示

デバッグパネル（`#usageStats`）に表示する開発用の観測情報一覧。ゲスト向けの主要UIではない。
表示内容: 会話制御方式・生成モデル・セッションID・外部生成リクエスト数・再試行数・トークン使用量。永続化失敗時はエラー行が追加される。

### 終了メモ

セッション終了後にデバッグパネルに表示される短いテキスト（`#endedNote`）。

- コード: `setSessionEndedNote()`

### 会話記録ダウンロードボタン

セッション終了後にデバッグパネルに表示される、会話記録・セッション情報・使用量をまとめた JSON をダウンロードするボタン（`#logBtn`）。

## アクセシビリティ

### WCAG

Web Content Accessibility Guidelines。W3C が定める Web アクセシビリティの国際指針。
達成基準は A / AA / AAA の3段階に分かれる。

- 推奨呼称: WCAG（「ウィーキャグ」と読む）
- 備考: 本プロジェクトでは AA 基準を対応目標とする

### JIS X 8341-3

WCAG を日本語化した JIS 規格。内容は WCAG とほぼ対応しており、国内公共機関の調達要件として参照されることが多い。
実装観点では WCAG と読み替えて差し支えない。

### AA基準

WCAG の達成基準レベル。A（最低）/ AA / AAA（最高）のうち中間。
一般的な Web サービスが対応目標とするレベルで、本プロジェクトもここを基準とする。

- 例: テキストのコントラスト比 4.5:1 以上、フォーカス可視性の確保

### ARIA

Accessible Rich Internet Applications。W3C が定める HTML のアクセシビリティ属性仕様。
`role` / `aria-*` 属性でセマンティクスと状態をスクリーンリーダーへ伝える。

- 例: `role="log"`, `aria-live="polite"`, `aria-hidden="true"`

### スクリーンリーダー

画面の内容を音声で読み上げるソフト。視覚障害者が主に使用する。
代表的な実装に NVDA（Windows）、VoiceOver（macOS / iOS）、TalkBack（Android）がある。

- 備考: 実機確認なしにアクセシビリティ対応が完了したとみなさない

### ライブリージョン

`aria-live` 属性を持つ要素。DOM が動的に変化したとき、スクリーンリーダーが自動で読み上げる領域。

- `aria-live="polite"`: 現在の読み上げが終わったあとに通知（会話表示向き）
- `aria-live="assertive"`: 即時割り込みで通知（エラー向き）
- `role="log"` は `aria-live="polite"` を暗黙に持つ

### フォーカス可視性

キーボード操作でフォーカスが当たったとき、どの要素にいるかが視覚的に分かること。
CSS では `:focus-visible` 疑似クラスで定義する。

- 備考: `outline: none` でブラウザデフォルトを消す場合は、必ず代替スタイルを用意する
- WCAG 達成基準: 2.4.7（A）/ 2.4.11（AA、WCAG 2.2）

### コントラスト比

テキスト色と背景色の相対輝度の差を表す比率。数値が高いほど読みやすい。
AA 基準では通常テキストで 4.5:1 以上、大きいテキスト（18pt 以上 / 14pt 太字以上）で 3:1 以上が必要。

- 備考: `--text3` は #636B78 に修正済み（約 5.4:1）

### prefers-reduced-motion

ユーザーが OS で設定するモーション軽減の設定値。前庭障害など、動きに敏感なユーザーへの配慮として参照する。
CSS メディアクエリ `@media (prefers-reduced-motion: reduce)` と JS の `window.matchMedia(...)` で検出できる。

- 対応例: アニメーション停止、タイプライター演出のスキップ
