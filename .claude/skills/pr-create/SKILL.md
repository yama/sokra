# プルリクエスト作成

このスキルは、GitHub のプルリクエスト本文を作成したり、プルリクエスト作成前の確認を行ったりするときに使う。
特定の AI 製品や GitHub 連携機能には依存しない。

## 目的

- プルリクエスト本文の構成を統一する
- 差分に存在する事実だけで概要文を書く
- レビュー未了や未確認事項を隠さない

## 参照先

- `.github/pull_request_template.md`
- `AGENTS.md`
- 必要なら `skills/review-workflow/SKILL.md`
- AI 向け文書の変更なら `skills/ai-doc-review/SKILL.md`

## 入力

最低限、次の情報を集める。

- ブランチ名
- 変更差分
- 関連するコミットや作業意図
- 実施済みのレビュー内容
- 実施済みまたは未実施のテスト、確認内容

差分を見ずにプルリクエスト本文を作らない。

## 手順

### 1. プルリクエスト作成の前提を確認する

次を確認する。

- 変更が `main` 以外の作業ブランチに乗っているか
- コミット前レビューまたは最終レビューが完了しているか
- 未解決の重大な問題を抱えたままではないか

### 2. 差分の主目的を一つに整理する

プルリクエストの `目的` は、差分の主目的に合わせて簡潔に書く。
複数の目的を長く列挙せず、なぜこの変更をまとめて出すのかが分かる形にする。

### 3. 主な変更を事実ベースで書く

`主な変更` には、差分に存在する変更だけを書く。

- 追加したもの
- 修正したもの
- 削除したもの
- 整理したもの

誇張した効果や、未確認の成果は書かない。

### 4. 確認内容を明示する

`確認内容` には、実施したレビューやテストを事実ベースで書く。

- 実施したレビュー
- 実施したテスト
- 未実施の確認

未実施のものを省略しない。

### 5. 未解決事項を隠さない

懸念点、制約、後続対応がある場合は `未解決事項` に書く。
なければ `なし` と明記する。

### 6. テンプレート構成へ合わせる

本文は `.github/pull_request_template.md` の構成に合わせる。
見出し名や区分を勝手にばらさない。

## ガードレール

- 差分にない内容を書かない
- レビューやテストを実施したように見せかけない
- 未解決事項を本文から隠さない
- 長い背景説明で要点を埋もれさせない
- コミットメッセージの寄せ集めで本文を済ませない

## 出力要件

プルリクエスト本文は、少なくとも次の4区分で返す。

- `目的`
- `主な変更`
- `確認内容`
- `未解決事項`
