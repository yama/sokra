# コミットメッセージ作成

このスキルは、Git の変更差分からコミットメッセージを生成するときに使う。
特定の AI 製品向けの書式や機能には依存しない。
コミット前レビューを終えた後に使う。

## 目的

- 変更差分に忠実なコミットメッセージを作る
- 主目的が一つに絞られたコミットメッセージにする
- 日本語の Conventional Commits 形式を守る

## 参照先

詳細な規約とプロンプトは次を参照する。

- `docs/commit-convention.md`
- `docs/commit-prompt.md`

このスキルでは規約本文を複製せず、判断手順だけを定義する。

## 入力

最低限、次の情報を集める。

- `git status --short`
- `git diff --staged`
- staged がなければ `git diff`
- 必要なら作業メモや変更意図

差分を確認せずにコミットメッセージを作らない。

## 手順

### 1. 差分の対象を確認する

まず、どのファイルが変更されたかを把握する。
staged がある場合は staged の差分を優先する。

### 2. 変更の主目的を一つ選ぶ

コミットメッセージには主目的を一つだけ反映する。

例:

- 新機能追加
- バグ修正
- リファクタ
- ドキュメント整備
- テスト修正

複数の目的が混ざる場合でも、subject には主目的だけを書く。

### 3. type を選ぶ

`docs/commit-convention.md` に従って、主目的に最も合う type を選ぶ。
迷う場合は「何が変わったか」ではなく「なぜその変更をしたか」に寄せて判断する。

### 4. scope の要否を判断する

影響範囲が明確で、付けた方が短く具体的になる場合のみ scope を付ける。
scope が曖昧なら付けない。

### 5. subject を作る

subject は日本語で、何をしたかが短く具体的に伝わる形にする。

- あいまいな語を避ける
- 差分にない内容を書かない
- 句点や感嘆符を付けない
- 50文字以内を目安にする

### 6. body の要否を判断する

body は必要な場合だけ付ける。
次のようなときは body を検討する。

- subject だけでは変更理由が伝わりにくい
- 変更点が複数あるが主目的は一つに揃っている
- 破壊的変更ではないが補足がないと誤解しやすい

body を付ける場合は、日本語の箇条書きで簡潔に書く。

### 7. footer の要否を判断する

破壊的変更がある場合のみ `BREAKING CHANGE:` を付ける。
それ以外では footer を追加しない。

## ガードレール

- 実際に変更していない内容を書かない
- 差分を読まずに推測で書かない
- 複数の異なる目的を一つの subject に詰め込まない
- 説明文、前置き、囲み文字を出力に含めない
- フォールバックとして無難な曖昧表現に逃げない
- このスキルはコミットメッセージ生成用であり、`git add` や `git commit` の並列実行を正当化しない

## 出力要件

出力はコミットメッセージ本文のみとする。

- 1行目: `type(scope): subject`
- 2行目: 空行
- 3行目以降: 必要な場合のみ日本語の箇条書き

body や footer が不要なら、1行目のみで終えてよい。
